AgentService is the one integration that needs no account. Its actions run inside AgentSDR and call no outside provider, so they are always available, cost nothing and never spend credits. Add one from **Add enrichment**, pick **AgentService**, map the input to a column and choose the results you want. Each result becomes its own column, like any other enrichment.

A value that cannot be cleaned is not an error. The row finishes with an empty result and, where there is one, a **Valid** column set to false, so one bad row never stops the run. An empty cell counts as a value that cannot be cleaned: the result is empty and **Valid** is false.

## Actions

| Action | Input | Results |
|---|---|---|
| **Normalize phone** | Phone (text or number) | Normalized Phone, Valid Phone, Mobile Phone, Second Phone |
| **Normalize email** | Email (text) | Normalized Email, Valid Email, Personal Email |
| **Domain from website** | Website (text or URL) | Domain |
| **Company domain from email** | Email (text) | Company Domain |
| **Normalize LinkedIn profile** | LinkedIn profile (text or URL) | Profile Slug, Profile URL |
| **Normalize name** | Full name (text) | First Name, Name 2 to Name 6, Last Name |
| **Normalize CNPJ** | CNPJ (text or number) | Normalized CNPJ, Valid CNPJ, Headquarters |
| **Normalize job title** | Job title (text) | Seniority Level |

### Normalize phone

Turns a phone number into the international format (for example `+5521986545481`), the shape WhatsApp and calls expect.

- A number typed without a `+` is read in your organization's default phone country (**Settings, General, Default phone country**). If none is set, Brazil (+55) is assumed.
- A cell with several numbers, separated by `/`, `;`, `,`, `|`, a line break or the words "ou", "e" and "or", keeps the first two valid ones: **Normalized Phone** and **Second Phone**. Repeated numbers count once. Numbers separated only by a space are read as one number.
- **Mobile Phone** is true for a mobile line and false for a landline. In the United States and Canada fixed and mobile lines share the same ranges, so it is always true there.
- A phone column that a file import read as a number works too.

### Normalize email

Lowercases the address, removes spaces and extra text such as `Ada <ada@acme.com>` or `mailto:`, and sets **Personal Email** to true for mailboxes like Gmail and Outlook.

### Domain from website

Gets the plain domain from a website address, without `https://`, `www.`, the port or the page path. It uses the same rule that identifies a company across the app.

### Company domain from email

Gets the company domain behind a work email. A personal mailbox such as Gmail returns nothing.

### Normalize LinkedIn profile

Gets the public profile name and the clean `https://www.linkedin.com/in/...` link from a profile URL, with or without tracking parameters. Company pages, Sales Navigator links and opaque member ids have no public name and come back empty.

### Normalize name

Splits a full name into one column per name: **First Name**, **Name 2**, **Name 3**, up to **Name 6**, plus **Last Name**. Particles (`da`, `de`, `do`, `das`, `dos`, `du`, `di`, `del`, `van`, `von`, `e`) and titles at the start (`Dr.`, `Sra.`, `Prof.`) are dropped, so `Maria da Silva dos Santos` gives `Maria`, `Silva` and `Santos`. A suffix such as `Junior` is kept as a name of its own.

- **Last Name** is always the last word, so it is `Santos` above, whatever position that is.
- Pick the columns you want when you add the enrichment. Positions a name does not have stay empty.
- A name with more than six words puts the rest in **Name 6**.
- A particle in first place is kept, so the first name is never blank. A single word has no last name.
- Columns created before this change hold the old result until you run the enrichment again.

### Normalize CNPJ

Removes dots, slash and dash so only the 14 digits are left, and checks the two verification digits. A CNPJ made of one repeated digit (such as `11111111111111`) is invalid.

- **Headquarters** is true for a headquarters (order block `0001`, digits 9 to 12) and false for a branch. It is empty when the CNPJ is invalid.
- An invalid CNPJ leaves **Normalized CNPJ** empty and **Valid CNPJ** false.
- A CNPJ column that a file import read as a number works too: the leading zeros the import dropped are put back. A text cell is never padded.
- CNPJs with letters (the alphanumeric format) are not supported yet and come back invalid.

### Normalize job title

Reads a job title in Portuguese or English and returns one seniority level, ignoring accents and case. The `Seniority Level` column holds the level in Portuguese, and `Level Code` beside it holds a fixed code, the same in every language, for filters and integrations:

| Level | Code | Examples |
|---|---|---|
| C-level | `c_level` | CEO, Presidente, Sócio, Founder, Chief Revenue Officer |
| VP | `vp` | Vice-presidente, VP of Sales |
| Diretor | `director` | Diretor, Sales Director, Head of Growth |
| Gerente | `manager` | Gerente, Product Manager |
| Coordenador/Supervisor | `coordinator` | Coordenador, Supervisor, Líder |
| Analista/Especialista | `analyst` | Analista, Especialista, Business Analyst |
| Assistente/Estagiário | `assistant` | Assistente, Estagiário, Auxiliar |
| Não identificado | `unknown` | any other title |

- A title with several roles gets the highest one: `Sócio-diretor` is `c_level`.
- An assistant who works for someone is `assistant`: `Assistente de Diretoria` and `Assistant to the CEO` are not directors. When the assistant word is part of the role itself, the role wins: `Diretor Assistente` is `director` and `Assistant Manager` is `manager`.
- Whole words only: `Gerenciamento de Projetos` and `Diretoria` alone are `unknown`.
- An empty title gives an empty result.
- `Owner`, `Partner` and `Lead` are not read as levels, because of titles like `Product Owner` and `Lead Developer`.
